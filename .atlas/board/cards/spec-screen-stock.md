**순수 조회 화면.** 등록·수정 없음. 같은 재고를 품목·창고·LOT 세 축으로 봄.

### 목록 — 품목 중심

| 열 | 원본 |
|---|---|
| 품목코드 · 품목명 | `Item` |
| 품목그룹 | `item_group` |
| 현재고 (전 창고 합) | `Bin.actual_qty` 합 |
| 예약 | `Bin.reserved_qty` — 작업지시가 잡아둔 분 |
| 입고 예정 | `Bin.ordered_qty` |
| **예상 재고** | `Bin.projected_qty` |
| 안전재고 미만 ● | `Item.safety_stock` 대비 |
| 단위 | `stock_uom` |

**필터** — 품목그룹 · 창고 · 부족만 · 배치추적 여부 · 검색어(코드·품명·고객 품번)

### 상세 — 별도 화면 (`[[decision-ui-shell]]` B 예외 기준 2)

| 구역 | 내용 |
|---|---|
| 요약 | 총재고 · 예약 · 입고예정 · 예상재고 · 안전재고 |
| 창고별 잔량 | 창고 × 수량 |
| **LOT별 잔량** | 배치 · 수량 · 생산일 · 설비 |
| 입출고 이력 | 날짜 · 구분 · 수량 · 문서 링크 (`Stock Ledger Entry`) |
| **재고 변동 차트** | 기간별 잔량 추이 |

### 시점

**현재고 + 예정 반영.** `Bin` 에 이미 계산돼 있는 값을 표시만 함:
`actual_qty`(현재) · `reserved_qty`(예약) · `ordered_qty`(입고예정) · `projected_qty`(예상).

## Why

**품목 중심을 기본 축으로** — "이 품목 지금 몇 개 있나"가 가장 잦은 질문. 창고·LOT은 상세에서 펼침.
창고 중심은 창고 담당에게, LOT 중심은 품질·추적에게 유용하지만 각각 필터와 LOT 추적 화면이 담당.

**예정 반영을 넣는 이유** — 계산이 이미 `Bin` 에 있어 표시 비용이 0이고,
"지금 있나"보다 "곧 부족한가"가 생산 판단에 직접 쓰임.

## Memory

데이터 원천: `Bin`(품목 × 창고별 집계), `Stock Ledger Entry`(모든 이동 기록),
`Batch`(LOT). 별도 저장 없이 조회만.

LOT별 잔량에는 `[[decision-lot-rule]]` 의 Batch custom field(생산일·설비·조·금형·작업지시)가
같이 보임 — 추적 화면으로 넘어가지 않아도 1차 판단이 가능.

재고 이동을 **일으키는** 화면(입출고·실사·출하)은 2차. 1차에서는 조회만 하고
실제 이동은 실행 현황의 작업 종료(제조 전표)와 Desk 뒷문이 담당.

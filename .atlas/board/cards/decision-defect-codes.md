ERPNext에 불량 코드 마스터가 없음 → **신규 DocType `MES Defect Code`.**

| 항목 | 결정 |
|---|---|
| 기록 범위 | **현상 필수 + 원인 선택** (처분은 부적합 처리에서 별도) |
| 목록 출처 | **기본 제공 + 업체 추가** |
| 공정별 필터 | **안 함 — 전체 목록.** 코드 수가 많아지면 재검토 (문진) |

### 구조

```
MES Defect Code (현상)
  code, name        예: DF-01 치수이탈
  category          치수 / 외관 / 기능 / 조립 / 기타
  is_standard       기본 제공 여부
  disabled

MES Defect Cause (원인)
  code, name        예: CS-01 금형 마모, CS-02 조건 이탈, CS-03 자재 불량, CS-04 작업 실수
```

### 입력 흐름

```
작업자 (실행 화면):  수량 20  +  현상 [치수이탈 ▼]          ← 필수
품질 담당 (사후):    원인 [금형 마모 ▼]                      ← 선택, 나중에 붙임
```

### 기본 제공 목록 (업종 공통만)

| 분류 | 코드 |
|---|---|
| 치수 | 치수이탈 |
| 외관 | 표면 흠집 · 오염 · 변색 |
| 조립 | 오조립 · 누락 |
| 기타 | 파손 · 기타 |

업종 고유(도통불량·미성형·버·웰드라인 등)는 업체가 추가.

## Why

**작업자는 현상만 안다** — 흠집을 본 순간 원인(금형 마모인지 조건 이탈인지)은 모름. 입력 시점에
현상만 받고 원인은 품질 담당이 사후에 붙이는 구조가 실제 업무 순서와 일치. 원인까지 있어야
"흠집의 대부분이 금형 마모"가 나와 개선 지점이 정해짐 — 현상만으로는 "흠집 30%"에서 끝남.

**자유 입력이 아니라 코드인 이유** — "버"·"버어"·"burr"·"테두리 삐져나옴"이 다 다른 값이 되어
집계 불가. 미리 정한 목록에서 고르게 해야 함.

**기본 목록 + 추가** — 설치 직후 바로 쓰되 업종 고유 항목은 업체가 등록. 도입 첫날부터
백지 등록 작업을 시키지 않음.

## History

- 공정별 필터(코드마다 적용 공정 지정) 제안 → 보류. 전체 목록으로 시작하고
  코드 수·오입력 실태를 보고 판단 (문진 항목).

## Memory

1차 실행 화면의 임시 사유 3~5개(`[[spec-screen-execution]]`)가 이 마스터의 기본 제공 목록으로
흡수됨 — 임시 코드로 쌓인 데이터는 카테고리 매핑으로 승계.

원인 코드는 `[[decision-mold-shot-count]]` 의 마모 판정과 연결 — 불량 코드에 금형 축이 있어야
"이 금형 로트만 불량률 높음"이 분해됨. 단 `use_mold` 꺼짐이면 금형 마모 원인은 안 보임
(`[[decision-mold-usage-switch]]`).

처분(재작업·선별·특채·폐기)은 다음 항목 **부적합 처리**에서 — 권한과 재고 이동이 얽혀 별도 설계.

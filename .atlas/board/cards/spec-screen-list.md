화면 22개. 체크 = 상세 설계 완료. 미체크는 이름·목적만 잡아둔 상태.

### 모니터링
- [ ] **대시보드** — 오늘의 생산·품질·설비·재고 예외를 한 화면에서 판단. 로그인 후 첫 화면
- [ ] **리포트** — 표준 리포트 모음 (생산실적·불량·금형·OEE·재고)

### 기준정보
- [x] **품목** — 원자재·반제품·완제품 등록, 고객 품번 매핑
- [x] **BOM** — 자재 구성과 공정(라우팅 적용). 라우팅·공정 마스터는 뒷문 관리
- [ ] **금형** — 캐비티·타수·수명·위치·소유
- [x] **설비** — 호기·유형·톤수, 현재 걸린 금형 (근무 캘린더는 2차)
- [ ] **작업자** — 인원·소속·근무조
- [ ] **품질기준** — 검사 항목·규격·관리한계
- [ ] **문서** — 도면·작업표준·성형조건표 개정과 유효본
- [ ] **거래처** — 고객·공급처·외주처

### 생산
- [ ] **생산계획** — 수요를 모아 소요 전개, 작업지시 일괄 생성
- [x] **작업지시** — 지시 발행·상태·일정 (금형 충돌은 use_mold 켜짐일 때)
- [x] **실행 현황** — 1차는 PC(보기+입력). 폰 입력 전용 페이지는 모바일 단계

### 품질
- [ ] **검사** — 수입·공정·출하를 한 화면에서 유형 필터로
- [ ] **불량·처분** — 불량 판정, 선별·재작업·폐기

### 재고
- [x] **재고 조회** — 품목 중심 + 창고·LOT 펼침, 예정 반영
- [ ] **입출고** — 입고·불출·반납
- [ ] **실사** — 실사 수량 입력과 차이 확인
- [ ] **출하** — 납품, 거래명세서, LOT 라벨
- [ ] **외주** — 발주·사급 출고·가공품 입고를 한 화면에서 단계 탭으로

### 추적·설정
- [x] **LOT 추적** — 양방향 트리 + 회수 범위 요약
- [ ] **MES 설정** — LOT 분기 플래그, 기본값, 업체별 옵션

## Why

합치고 나눈 기준:

| 판단 | 결정 | 근거 |
|---|---|---|
| 기준정보 8개 | **개별 화면** | 각각 필드·동작이 다름. 탭으로 묶으면 한 화면이 비대해짐 |
| 재고 4개 | **분리 유지** | 쓰는 사람과 빈도가 다름 — 조회=상시, 실사=월 1회, 출하=일일 |
| 검사 | **1화면 + 유형 필터** | 수입·공정·출하가 입력 형식이 같고 대상만 다름 |
| 외주 | **1화면 + 단계 탭** | 한 건이 발주→출고→입고를 순서대로 지나가므로 흐름을 한 화면에서 |

## Memory

**제외한 화면과 이유**
- 알림함 — Frappe 기본 알림 사용 (`[[decision-ui-architecture]]` Desk 셸)
- 사용자·권한 관리 — Desk 뒷문에서 시스템 관리자가 처리
- 설비 보전 — 로드맵 7번에서 설계 후 추가. 지금은 자리만

설계 순서: ① 이 목록 확정 → ② **공통 뼈대**(전체 22개 기준) → ③ 최소 동작 묶음만 상세 →
④ 나머지 묶음 순차. 뼈대를 전체 기준으로 잡는 이유는 나중에 화면이 늘 때 메뉴 재편·공통 부품 변경으로
기존 화면을 다시 손대는 일을 막기 위함.

데이터 설계가 먼저 끝나 있어(마스터·LOT·외주·계획) 화면 추가는 대부분 순수 추가가 됨.

**금형은 전제가 아니라 스위치.** `MES Settings.use_mold` 하나로 10개 지점이 함께 움직임.
**기본값 = 꺼짐.** 문진 8번(금형 모듈 사용 여부)이 곧 이 값.

| # | 지점 | 켜짐 | 꺼짐 |
|---|---|---|---|
| 1 | 작업지시 생성 폼 | 금형 선택 필드 | 필드 없음 |
| 2 | 작업지시 검증 | 금형 중복 배정 경고 | 검증 안 함 |
| 3 | 작업지시 목록 | 금형 열 | 열 없음 |
| 4 | 현장 실행 화면 | `금형 교체` 버튼, 금형·타수 표시 | 없음 |
| 5 | LOT 분기 | `lot_split_on_mold_change` 사용 | **자동 꺼짐** |
| 6 | Batch 필드 | `mes_mold` 채움 | 빈 값 |
| 7 | 타수 가산 훅 | 실적마다 가산 | 동작 안 함 |
| 8 | 설비 화면 | "현재 걸린 금형" 열 | 열 없음 |
| 9 | 대시보드 | 금형 수명·보전 예외 카드 | 카드 없음 |
| 10 | 좌측 메뉴 | 금형 화면 노출 | 메뉴에서 숨김 |

**금형 사용 시 배정 방식** — 작업지시에 금형 필드(custom). 그 품목에 연결된 금형이 하나면 자동 선택,
여러 개면 선택. 공정마다 다른 금형을 쓰는 구조는 지원하지 않음(요구 발생 시 Job Card 단위로 확장).

## Why

금형이 없는 업종(조립·가공 위주)에서 금형 개념이 화면·검증·LOT 분기에 계속 끼어드는 문제가 반복됨.
지점마다 "금형이 있다면…"을 따로 판단하는 대신 설정 하나를 읽게 함 — 코드 분기가 아니라
**설정 조회**라 유지 비용이 낮음.

판정은 훅에서 (`[[decision-business-logic-placement]]`):

```python
if not settings.use_mold:
    return          # 타수 가산·검증을 조용히 통과
```

기본값을 꺼짐으로 둔 이유: 우선 검증 대상이 하네스이고, 금형(압착 애플리케이터) 관리는
필요한 업체에서 켜면 됨. 켜는 비용은 체크 하나.

## Memory

금형 자체의 설계는 `[[decision-mold-doctype]]`(필드·Asset 링크 방향),
`[[decision-mold-shot-count]]`(타수 가산·수명 경고)에 그대로 유효 — 이 카드는 **활성 여부**만 다룸.

금형 마스터를 1차 묶음에서 뺀 것(`[[spec-mvp-scope]]`)과도 정합.
켜는 고객이 오면 금형 화면을 2차에서 만들고 `use_mold` 를 켬.

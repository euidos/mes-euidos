### 목록

| 열 | 원본 |
|---|---|
| 호기 | `machine_code` (custom) |
| 설비명 | `workstation_name` |
| 유형 | `machine_type` (custom) — 압착기/사출/프레스/조립대/검사기 |
| 능력 | `tonnage` (custom) — 사출·프레스만 |
| 현재 걸린 금형 | `MES Mold.current_workstation` 역조회 |
| 진행 중 작업지시 | Work Order 상태에서 |
| 사용/중지 | `disabled` |

**실시간 가동 상태 열 없음.**

### 상세 — 드로어

| 구분 | 필드 | 편집 |
|---|---|---|
| 기본 | 호기·설비명·유형·능력·설명 | 편집 |
| 원가 | 시간당 원가 (`hour_rate`, `workstation_costs`) | 편집 |
| 계획 기준 | 근무시간표(`working_hours`) · 휴일 목록(`holiday_list`) · 동시 작업 수(`production_capacity`) | **읽기 전용** — 편집은 Desk 뒷문 |

`계획 기준`은 "지켜야 하는 규칙"이 아니라 **"예측의 전제"** 임을 화면에 명시.

### 별도 화면 (이력·추세)

가동·비가동 추이 · 생산 실적 · 금형 장착 이력 — `[[decision-ui-shell]]` B 예외 기준 2.

### 계획 설정

| 설정 | 값 |
|---|---|
| `allow_overtime` | **끔** |
| `allow_production_on_holidays` | **끔** |
| 예외 | 휴일 목록에서 **날짜 단위**로만 (특근일은 그날을 휴일에서 제거) |

## Why

**실시간 가동 상태를 표시하지 않는 이유**: 실적 입력이 이벤트·마감 시점(하루 2~5회)이라
"최근 실적 = 가동" 판정은 하루 대부분을 정지로 표시함 — **틀린 정보를 확신 있게 보여주는 꼴**.
설비 부하·일정은 계획 화면의 간트가, 지금 문제가 있는 설비(비가동 진행 중·금형 수명 도달)는
대시보드 예외 카드가 담당.

**연장근무를 계획에 반영하지 않는 이유**: ERPNext는 `working_hours` 가 요일 무관 고정이라
**날짜별로 시간을 늘리는 자리가 없음**. 전역 `allow_overtime` 은 늘 켜짐/꺼짐이라 켜두면 예정일이
항상 낙관적으로 나옴. 반영하지 않으면 예정일이 보수적으로 나오고 실제로는 당겨짐 —
납기 회신 관점에서 안전한 방향으로 틀림.

**계획은 실적을 막지 않음** — 근무시간표는 완료 예정일 계산에만 쓰이고, 시간표에 없는 시간에 작업해도
실적·재고·LOT은 정상 기록됨. 시간표가 틀리면 **예측 정확도만** 떨어짐.

## Memory

**날짜별 예외의 반영 범위** (ERPNext 구조):

| 데이터 | 단위 | 날짜별 예외 |
|---|---|---|
| `working_hours` | 요일 무관 고정 시간대 | 불가 |
| `holiday_list` | 날짜 목록 | **가능** |

따라서 휴무·특근은 표현되고 연장근무 시간대는 표현 불가. 설비마다 다른 휴일 목록을 붙일 수 있어
**라인별 특근**은 가능.

**한국 공휴일은 수동 등록(A안).** ERPNext에 주말 자동 생성(`weekly_off`)은 있으나 한국 공휴일
자동 등록은 없음. 공휴일 데이터의 성질 — 설날·추석·부처님오신날은 음력이라 매년 날짜가 바뀌고,
대체공휴일 규칙이 있으며, 임시공휴일·선거일은 그해에 갑자기 생김. **매년 갱신이 필요한 데이터**.

더 중요한 점: **제조업은 법정공휴일 = 휴무가 아님.** 교대제 공장은 정상 가동하는 경우가 많고,
회사 지정 휴무(하계휴가·창립기념일·연휴 조정)가 따로 있음. 그래서 공휴일 목록을 그대로 넣으면 틀리고
**회사 달력이 진짜 기준**임. 자동화(공공데이터 특일정보 API)를 붙여도 "쉴지 말지"는 사람이 판단해야
하므로 절감 효과가 작아 후보로만 둠.

**근무 캘린더 화면은 2차.** 1차에서는 휴일 목록을 Desk 뒷문에서 날짜 편집. 특근이 잦은 고객이 오면 앞당김.

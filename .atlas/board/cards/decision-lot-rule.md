| 기준 | A. 조 단위 | **B. 작업지시(금형 세팅) 단위 + 조건 분기** | C. 개별 시리얼 |
|---|---|---|---|
| 1 LOT 규모 | 수백~수천 | **수천~수만** | 1 |
| 회수 범위 | 최소 | 적정 | 최소 |
| 관리 비용 | 높음 | 중간 | 매우 높음 |
| 사출·프레스 실무 | 요구 강한 곳만 | **기본선** | 안전부품만 |

**채택: B.** setup-to-setup = 성형 조건이 동일하게 유지되는 최대 구간 → "동일 조건 생산 단위"라는 LOT 정의와 물리적으로 일치.

```
{일자}-{호기}-{순번}
260725-IJ03-001
  │      │     └ 3자리. 조건 분기 순번
  │      └ IJ 사출 / PR 프레스 + 2자리 호기
  └ YYMMDD (WO 시작일)
```

| 분기 사유 | 분리 | 설정 플래그 | 기본값 |
|---|---|---|---|
| 작업지시(금형 세팅) 시작 | O | — | 항상 |
| 금형 교체 | O | `lot_split_on_mold_change` | ON |
| 원료 로트 변경 | O | `lot_split_on_material_batch` | ON |
| 성형조건 변경·재작업 | O | `lot_split_on_param_change` | ON |
| 설비(호기) 변경 | O | `lot_split_on_workstation` | ON |
| 날짜 변경 | X | `lot_split_on_date` | OFF |
| 조 교대 | X | `lot_split_on_shift` | OFF |

조회는 **코드 파싱 금지**, Batch custom field로 — 플래그와 무관하게 **항상 기록**:
`mes_production_date` `mes_workstation` `mes_shift` `mes_mold` `mes_work_order`.

## Why

LOT 크기 = 클레임 1건의 회수 단위. 수천~수만이 정상 범위, 10만 초과면 회수 리스크 과다,
수백이면 관리 비용이 이득을 넘음. IATF 16949 / ISO 9001도 단위를 못 박지 않고
"동일 조건 생산 단위로 정의 후 일관 적용, 추적·회수 가능"만 요구.

분기에 안 쓰는 필드도 채우는 이유: 나중에 조 단위로 켤 때 과거 Batch에 조 정보가 없으면 소급 불가.

## History

- 2026-07-27 초안: **일자 + 호기 + 조** 단위, 코드 `260725-IJ03-N-001` — `superseded`
  - 폐기 사유: 조를 LOT 경계로 삼으면 ① 교대가 박스 중간에 걸려 LOT 경계와 포장 경계 불일치
    ② 야간조 자정 넘김 시 일자 해석이 사람마다 갈림 ③ 교대마다 실적 마감 부담·누락
    ④ 출하 시 LOT 파편화(납품서에 LOT 여러 줄) ⑤ 고객 라벨 요구는 대개 생산일+호기까지
    ⑥ 2교대↔3교대 개편 시 코드에 박힌 `D/N/S` 의미가 바뀜
  - 조 단위 회수 이점은 포기. 다만 야간조 이슈는 대개 조건 변경·금형 이상으로 나타나 그 사유로 이미 분리됨.
- 수량 상한(`max_lot_qty`) 안은 기각 — 조건이 안 바뀌었는데 개수로 끊는 건 LOT 정의와 불일치.

## Memory

코드 설계 근거:
- 고정폭 유지 — 가변 길이 세그먼트(품번 등)를 섞으면 정렬·스캔이 깨짐
- **품번 제외** — Batch가 이미 Item에 종속. 라벨에는 품번 별도 인쇄
- **금형 제외** — 금형 교체는 순번 증가 사유라 `-002` 로 표현됨
- **조 제외** — History 참조
- **일자 선두** — Batch 목록 정렬이 곧 시간순
- 순번 3자리 — 이미 발번된 코드는 소급 변경 불가하므로 여유 확보

**원료 로트를 Batch 필드로 복제하지 않음** — 제조 Stock Entry에 소비 배치가 남아 역추적 경로가
이미 존재. 복제하면 두 값이 어긋나는 시점이 옴.

원자재 `has_batch_no`: 레진·마스터배치·코일 등 추적 대상만 ON, 포장재 등 부자재 OFF.

C(개별 시리얼) 전환 경로: 요구 고객이 생기면 해당 품목만 `has_serial_no`.

발번 구현은 `[[decision-lot-issuer]]`, 업체별 설정 항목은 `[[table-tenant-options]]`.

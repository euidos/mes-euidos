## Memory

이 카드의 목적: **제품 라인 하나로 여러 공장에 들어가되, 공장별 차이를 코드 분기가 아니라
설정·마스터·문진으로 흡수**하기 위한 목록. 새 공장 도입 시 이 표가 곧 문진표가 됨.

원칙 세 가지 (`[[decision-lot-issuer]]` 논의에서 도출):
1. **나중에 켜도 싼 것** = 분기 규칙, 정적 참고 정보. 플래그나 custom field로 두거나 아예 안 만든다.
2. **나중엔 못 되돌리는 것** = ① 기록하지 않은 운영 데이터 ② 이미 발번된 코드 형식
   ③ 흩어진 발번 지점. → 안 쓰는 필드도 항상 채우고, 코드 형식은 여유 있게, 발번은 한 함수로.
3. 업체 선택지를 늘리는 것 자체가 비용 — 기본값이 명확한 항목만 설정으로 승격.

13번(금형 이력 정보)이 1번 원칙의 사례: 금형 등록 시 사람이 입력하는 정적 정보라 **소급 입력이 가능**.
운영 중 자동 수집되는 값(타수·조·금형)과 성격이 다르므로 기본 미제공이 안전.

14번(배포 모델)은 다른 항목의 설정 단위를 좌우함: 사이트 1개 = 공장 1개면 `MES Settings`(단수)로
충분하고, 한 사이트에 여러 공장이면 설정을 Company 단위 자식 테이블로 내려야 함.
현재는 사이트 분리 전제. 필드 자체는 살아남으므로 나중 전환 비용은 낮음.

미설계 항목은 `[[spec-design-roadmap]]` 의 해당 단계에서 결정되면 기본값을 채운다.

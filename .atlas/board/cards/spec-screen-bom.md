**별도 화면** (드로어 아님 — 자식 표 여럿 + 트리). 라우팅·공정 마스터는 화면 없이 Desk 뒷문 관리.

### 목록

| 열 | 원본 |
|---|---|
| 대상 품목 | `item` |
| BOM 번호 | `name` |
| 수량 | `quantity` |
| 라우팅 | `routing` |
| 자재 수 | `items` 행 수 |
| 상태 | 초안 / 활성 / 비활성 / 취소 |
| 기본 BOM ● | `is_default` |

**필터** — 품목 · 품목그룹 · 활성만 · 라우팅
**표시 정책** — 활성 BOM만 목록에. 이전 버전은 상세의 `이전 버전` 탭에서

### 상세

```
┌ BOM-FG-A100-001                      [새 버전] [비활성화] ⋯ ┐
│ 대상 품목  FG-A100        수량 1 EA        활성 ●            │
│ 라우팅     하네스 표준 (압착→조립→검사→포장)                  │
├──────────────────────────────────────────────────────────────┤
│ [자재] [공정] [부산물] [구조] [이전 버전]                     │
├──────────────────────────────────────────────────────────────┤
│  품목        수량   단위  창고       하위BOM                  │
│  전선-2SQ    2.0    m     원자재                              │
│  SFG-W01     1      EA    반제품    BOM-SFG-W01-002 →        │
└──────────────────────────────────────────────────────────────┘
```

| 탭 | 내용 | 편집 |
|---|---|---|
| 자재 | 품목·수량·단위·창고, 하위 BOM 링크 | 초안일 때만 |
| 공정 | 라우팅에서 복사된 공정·설비·표준시간 | **읽기 전용** |
| 부산물 | Scrap 산출(재생재), 공정 손실률 | 초안일 때만 |
| 구조 | 다층 트리 — **한 단계씩 지연 로딩** | 읽기 |
| 이전 버전 | 같은 품목의 과거 BOM | 읽기 |

**원가**는 전 사용자에게 노출 (재료비·가공비·총원가). 권한으로 가리지 않음.

### 상태별 화면

| 상태 | 편집 | 버튼 |
|---|---|---|
| 초안 | 전 필드 | `활성화` |
| 활성 | **읽기 전용** | `새 버전` `비활성화` `기본으로 지정` |
| 비활성 | 읽기 전용 | `활성화` |

### 검증

- 순환 참조 금지 (ERPNext 기본)
- 같은 품목의 기본 BOM은 1개
- 자재 수량 0 이하 금지
- 라우팅 적용은 **공정이 비어 있을 때만** — 이미 있으면 덮지 않음

## Why

**제출 후 수정 불가는 프레임워크 규칙** — Frappe `docstatus` 0 초안 / 1 제출 / 2 취소.
BOM은 `is_submittable: 1`.

잠그는 이유: 제출 문서가 다른 문서의 근거이기 때문. BOM → 작업지시 → 자재 예약·소비 → 재고 전표 → 원가.
사후 변경 시 **"이 LOT은 어떤 구성으로 만들어졌나"에 답할 수 없게 됨** —
`[[decision-traceability-screen]]` 의 역방향 추적이 "그때의 BOM"을 가리켜야 성립.
새 버전을 별도 문서로 만들면 과거 작업지시가 옛 BOM을 계속 가리켜 이력이 정합함.

**전부 잠기는 건 아님** — `allow_on_submit` 필드 확인 결과 운용 플래그와 원가 산정 기준은 열려 있음:
`is_active` `is_default` `rm_cost_as_per` `buying_price_list`
`set_rate_of_sub_assembly_item_based_on_bom`. 구성(자재·공정)만 잠김. 설계상 합리적.

**원가를 가리지 않는 이유**: 표준원가는 현장·생산 담당도 판단 근거로 씀. 권한 분기를 만들면
화면마다 처리가 늘고, 정작 단가를 알아야 할 사람이 못 보는 경우가 생김.
단가 노출을 꺼리는 업체가 있으면 그때 역할 기반으로 가림(문진 대상).

**다층 트리를 지연 로딩하는 이유**: 재귀 전개라 깊으면 느려짐. LOT 추적 화면의 깊이 상한과 같은 근거.

## Memory

**라우팅·공정 마스터에 화면을 만들지 않은 이유**: 하네스처럼 공정 흐름이 하나인 업종은 라우팅 레코드가
1~3개로 끝나고 평생 몇 번 열림. 등록·수정은 Desk 뒷문(도입 초기 1회, 이후 연 몇 회).
BOM 화면에서는 **선택 드롭다운만**. 라우팅 종류가 많거나 자주 바뀌는 업체가 오면 그때 화면 추가(문진).

같은 이유로 **BOM에서 공정 직접 편집 경로도 열지 않음** — 특수 제품은 뒷문에서 처리.
(`[[decision-routing]]` 은 `routing` 을 비우고 operations를 직접 채우는 경로를 허용하지만 화면에서는 미노출)

**라우팅 수정의 함정** (화면을 만들 때 반영할 것): 표준시간을 고쳐도 복사 시멘틱 때문에 기존 BOM에
반영되지 않아 "같은 공장 안에서 표준시간이 두 벌"이 됨. 라우팅 편집 화면을 만들 때는
`이 라우팅을 쓰는 BOM 42건 / 신규부터 적용` 안내를 함께 붙일 것.

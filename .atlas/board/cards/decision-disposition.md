| 항목 | 결정 |
|---|---|
| 판정 문서 생성 | **불량 등록건마다 자동** — 등록되면 반드시 판정 대상 |
| 재작업 | **정식 작업지시 발행** (프로세스 상세는 문진) |
| 특채 승인 | **기록만** — 승인번호·일자·첨부. Workflow는 후속 |

### 흐름

```
불량 발생 (실행 화면 등록, 현상 코드 포함)
   ↓  자동
불량 창고 이동 + 판정 대기 문서 생성
   ↓  품질 담당 판정
┌─ 선별    → 양품은 원 창고 복귀, 잔여는 재판정
├─ 재작업  → 재작업 작업지시 → 완료 후 재검사 → 양품 복귀 (LOT 순번 +1)
├─ 특채    → 승인번호·일자·근거 첨부 기록 → 양품 취급 (특채 표시 유지)
└─ 폐기    → 재고 제거. 사출이면 분쇄 → 재생재 입고 가능
```

용어: **선별** = 좋은 것만 골라냄 · **재작업** = 고쳐서 다시 씀 · **특채** = 규격 벗어났지만
고객 동의 받고 사용 · **폐기** = 버림.

## Why

**판정 자동 생성** — "불량 창고에 있는데 판정 안 된 것"이 항상 시스템에 보이므로 누락이 구조적으로
불가능. 수동 생성은 품질 담당이 빠뜨리면 그대로 묻힘.

**재작업 = 정식 작업지시** — LOT 분기 규칙에 "재작업 = 순번 +1"이 이미 있고
(`[[decision-lot-rule]]`) 그것이 성립하려면 재작업이 정식 작업이어야 함. 재작업 실적·시간이 잡혀
재작업 비용이 보이는 것도 개선 근거.

**특채 승인은 기록만** — Workflow는 나중에 붙여도 데이터 구조가 바뀌지 않음
(`[[decision-mes-document]]` 와 같은 근거). 지금은 승인 근거 보존으로 충분.

## Memory

앱 초기 임포트에 `defect_disposition` DocType 스켈레톤이 이미 있음 — 구현 시 이 설계에 맞게 재정의.

폐기 → 재생재 경로는 `[[decision-warehouse-structure]]` 의 scrap 처리와 연결.
특채 표시는 Batch에 남겨 추적 화면에서 보이게 — 특채 LOT이 어디 납품됐는지가 클레임 시 필요.

**문진**: 재작업 프로세스 상세 — 재작업을 별도 지시로 발행하는 운영이 맞는지, 원 지시에 이어
붙이는지, 재검사를 누가 하는지. 업체 관행 확인 후 화면 상세 확정.

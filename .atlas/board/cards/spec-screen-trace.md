**한 화면 양방향 트리.** 재귀 쿼리 하나를 위·아래 두 방향으로 호출 (`[[decision-traceability-screen]]`).

### 구성

```
┌ LOT 추적 ───────────────────────────────────────────────┐
│  [ 260801-IJ03-001            ]  🔍                     │  검색창 입력
├─────────────────────────────────────────────────────────┤
│  ▲ 무엇으로 만들었나 (역방향)                            │
│    ├ 전선 W-2405        200m    입고 7/28  (주)대한전선  │
│    ├ 터미널 T-118       4,000EA 입고 7/20               │
│    └ 설비 IJ03 · 작업자 김OO · 도면 Rev.3 · 조건표 Rev.2 │
│                                                          │
│  ● LOT 260801-IJ03-001    FG-A100   6,900개  8/1 생산   │
│                                                          │
│  ▼ 어디로 갔나 (정방향)                                  │
│    ├ 출하 8/5  현대차   4,200                            │
│    ├ 출하 8/6  기아     1,800                            │
│    └ 재고            완제품창고   900                    │
├─────────────────────────────────────────────────────────┤
│  회수 범위 요약                        [엑셀 내보내기]   │
│    대상 LOT 1건 · 총 6,900개                             │
│    출하 6,000 (현대차 4,200 / 기아 1,800) · 재고 900     │
└─────────────────────────────────────────────────────────┘
```

| 항목 | 결정 |
|---|---|
| 표현 | **트리(들여쓰기 목록)** |
| 진입 | **검색창 직접 입력** (LOT · 원료 배치 · 품목) |
| 깊이 | 기본 5단계, "더 보기"로 확장 |
| 하단 | **회수 범위 요약 + 엑셀 내보내기** |

## Why

**트리를 택한 이유** — 클레임 대응에서 이 화면을 캡처·인쇄해 고객에게 보내는 일이 실제로 생김.
그래프(노드·선)는 보기 좋지만 인쇄·전달에 약하고 노드가 많아지면 오히려 못 읽음.

**회수 범위 요약을 넣는 이유** — 이 화면의 목적이 리콜 범위 산정인데 트리만 보여주면 사람이 세야 함.
집계 한 줄이면 "회수 대상 6,000개, 고객 2곳"이 바로 나오고 그대로 제출 가능.
좁게 잡으면 불량이 시장에 남고 넓게 잡으면 과대 회수 — 정확한 수치가 곧 비용.

## Memory

데이터는 이미 존재하므로 추가 저장 없음: 소비·산출 배치 관계는 Stock Entry 상세의 `batch_no`,
출하처는 Delivery Note 배치 행, 설비·작업자·조·금형은 Job Card와 Batch custom field,
문서 개정은 Batch 문서 스냅샷.

**외주 구간 연결** — 유상사급은 입고 배치의 `원 출고 배치·문서` 참조로, 도급은 입고 시 받은
협력사 LOT으로 이어짐 (`[[decision-outsourcing-traceability]]`). 유상사급 구간을 트리에서
한 줄기로 합쳐 그릴지 구분해 표시할지는 구현 시 재검토 항목.

**진입 경로는 검색창만** — 다른 화면(재고 조회의 LOT별 잔량, 작업지시의 LOT 탭)에서 링크로 넘어오는
경로와 바코드 스캔은 비용이 작으므로 필요해지면 추가.

**재귀 깊이 상한 필수** — 다층 BOM이면 단계가 여러 개고, 순환 BOM이나 깊은 트리에서 화면이 멈춤.
구현 시 `batch_no` 인덱스 확인.

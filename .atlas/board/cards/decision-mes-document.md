| 기준 | A. 첨부 목록만 | **B. 개정 이력 + 유효본** | C. 승인 워크플로 포함 |
|---|---|---|---|
| 저장 | 파일 + 분류 | 파일 + 개정번호 + 유효/폐기 | B + 작성→검토→승인 |
| 현장 화면 | 최신 파일 링크 | **유효본만 노출** | 유효본만 노출 |
| 구버전 오작업 방지 | 불가 | 가능 | 가능 |
| 승인자 이력 | 없음 | 없음 | 남음 |
| 비용 | ~0 | 필드 몇 개 + 검증 1개 | Workflow 설정 + 역할 설계 |

**채택: B + LOT 자동 스냅샷.**

### 필드

```
MES Document
  문서번호, 문서명
  종류      → Select: 도면 / 작업표준 / 검사기준 / 성형조건표 / 포장사양
  대상 품목  → Link: Item       (품목별 문서)
  대상 금형  → Link: MES Mold   (금형별 조건표)
  개정번호   → Data (Rev.3)
  상태      → Select: 유효 / 폐기
  발효일    → Date
  파일      → Attach
```

같은 문서번호로 새 개정 등록 → 이전 것 자동 `폐기` (검증 1줄). 현장 화면은 `상태 = 유효` 만 노출.

### LOT 스냅샷

실적 등록 시점의 유효 문서를 Batch 자식 테이블로 복사. **작업자 입력 0.**

| 실무자 | 연결 O | 연결 X |
|---|---|---|
| 작업자 | 화면 동일, 입력 없음 | 동일 |
| 반장·기술 | 조건 개정 = LOT 분리 = 문서 기록이 한 줄로 이어짐 | LOT은 갈렸는데 근거가 안 남음 |
| 품질 (클레임) | Batch 열면 Rev 표시 — 5분 | 발효일 대조·기억 의존 — 반나절, 확신 없음 |
| 관리 (리콜) | `문서 = Rev.2` 필터 → 대상 LOT 즉시 | 기간 추정 → 과대 회수 또는 누락 |
| 심사 (IATF/ISO) | 화면 하나 | 설명 과정이 곧 지적 사항 |

## Why

A는 "현장이 구버전을 보는 것"을 못 막아서 마스터를 만드는 의미가 없음.
C의 승인 워크플로는 심사에서 요구되지만 Frappe `Workflow` 기능으로 **나중에 붙여도 데이터 구조가
바뀌지 않음** — 지금 만들면 역할·단계를 업체마다 다시 짜야 함.

스냅샷을 자동으로 하는 이유: 작업자에게 버전 입력을 시키면 반드시 틀림. 시스템이 유효본을 읽는 편이
정확하고 부담도 0.

## Memory

**유일한 함정**: 개정이 나왔는데 시스템에 등록하지 않으면 구버전이 유효본으로 남아 **틀린 스냅샷이
맞는 것처럼 기록됨**. 종이로만 굴리던 공장에는 문서 등록이 새 업무 부담이므로,
문서 개정을 시스템에서 관리할 의사가 있는지가 문진 항목 (`[[table-tenant-options]]` 21번).
의사가 없으면 `MES Document` 를 아예 안 쓰고 스냅샷도 비어 있음 — 금형 모듈과 같은 비활성 패턴.

사출에서 특히 중요한 문서는 **성형 조건표**(온도·압력·냉각시간). 조건 변경이 이미 LOT 분기 사유
(`lot_split_on_param_change`, `[[decision-lot-rule]]`)이므로 "조건 변경 = 문서 개정 = LOT 분리" 가
하나의 흐름으로 이어짐.

ERPNext 기존 기능 확인 결과: `File` 첨부는 어느 문서에나 붙지만 개정·승인 개념이 없고,
Document Revision 류의 DocType은 없음. 그래서 신규 DocType이 필요.

도면번호를 MES Mold에 넣지 않은 이유가 이 카드 — 문서는 여기서 일원 관리 (`[[decision-mold-doctype]]`).
